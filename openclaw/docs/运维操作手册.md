# OpenClaw 小说发布系统运维操作手册

## 1. 文档目的

本手册用于日常启动、停止、巡检和排查 OpenClaw 小说发布系统。

系统以飞书多维表为业务数据源，通过 ADB 控制五台云手机中的番茄作家助手。发布流程完全由 Python 脚本、固定页面坐标和 Android `uiautomator` 文本树完成，不依赖智能体截图识别。

## 2. 当前运行环境

- 项目目录：`D:\WorkSpace\Code\novel\openclaw`
- Python：项目虚拟环境 `.venv`
- 主入口：`closed_loop.py`
- 配置文件：`config\config.yaml`
- 密钥与本地环境：`config\.env`
- ADB 程序：由 `config\.env` 中的 `ADB_PATH` 指定

## 3. 发布任务完整流程

每个符合条件的章节任务都会依次执行：

1. 检查目标设备 ADB 在线状态。
2. 点击 Android HOME。
3. 强制停止番茄作家助手。
4. 重新启动番茄作家助手。
5. 退出“每周任务”等活动页面。
6. 点击底部“作品”。
7. 点击第一本绑定作品。
8. 验证进入“章节管理”或空作品的“开始创作”页面。
9. 检查章节是否已经发布、审核中或存在草稿。
10. 填写章节号、标题和正文。
11. 等待正文保存到云端。
12. 进入发布设置并选择“有使用AI”。
13. 提交章节并核对审核中或已发布状态。
14. 回写飞书章节任务表和发布记录表。
15. 返回章节管理安全页面。

已经存在的章节只核对状态，不会重复填写或重复提交。

## 5. 日常启动

### 5.1 启动前检查

进入项目目录：

```powershell
Set-Location D:\WorkSpace\Code\novel\openclaw
```

检查飞书、表结构、写权限和日志双写：

```powershell
.\.venv\Scripts\python.exe scripts\healthcheck.py
```

全部显示 `PASS` 后再启动服务。

检查 ADB：

```powershell
$adbExe = 'C:\Users\Administrator\AppData\Local\Android\Sdk\platform-tools\adb.exe'
& $adbExe devices -l
```

五台目标设备都应显示为 `device`，不能是 `offline` 或 `unauthorized`。

### 5.2 单次运行

用于上线前检查或手动触发一个扫描周期：

```powershell
.\.venv\Scripts\python.exe closed_loop.py --once
```

正常输出示例：

```text
{"produced": [], "published": []}
```

- `produced`：本轮完成生产的章节ID
- `published`：本轮提交或完成状态核验的章节ID
- 两个列表为空表示当前没有符合条件的任务，不代表程序异常

### 5.3 前台持续运行

适合观察测试：

```powershell
.\.venv\Scripts\python.exe closed_loop.py --continuous
```

按 `Ctrl+C` 停止。程序会关闭调度器、HTTP 客户端和设备网关。

### 5.4 Windows 后台运行

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_closed_loop.ps1
```

当前用户启动目录中包含：

```text
OpenClaw Novel Closed Loop.cmd
```

该启动项会在当前 Windows 用户登录后运行后台脚本。

## 6. 停止后台服务

先查找进程：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*closed_loop.py*--continuous*' } |
  Select-Object ProcessId, Name, CommandLine
```

只停止明确匹配 `closed_loop.py --continuous` 的 Python 进程：

```powershell
$servicePids = Get-CimInstance Win32_Process |
  Where-Object {
    $_.Name -eq 'python.exe' -and
    $_.CommandLine -like '*closed_loop.py*--continuous*'
  } |
  Select-Object -ExpandProperty ProcessId

foreach ($servicePid in $servicePids) {
  Stop-Process -Id $servicePid
}
```

不要结束其他 Python 或 ADB 进程。

## 7. 飞书任务操作

### 7.1 可以自动发布的章节

章节至少需要满足：

- 生产状态为已定稿、已审核或已完成
- 内容锁定状态为“是”或“人工锁定”
- 存在当前最终版本
- 小说自动发布开关开启
- 账号健康状态正常
- 账号阶段不是养号期
- 发布状态为待发布
- 已到计划发布时间

### 7.2 人工审核章节

未完成人工审核的章节可以一直保留，程序会跳过该章节，不会阻塞其他小说。

审核通过后需要确认：

- 生产状态：`已定稿/Finalized` 或 `已完成`
- 内容锁定状态：`是/Yes` 或 `人工锁定`
- 发布状态：按排期进入待发布

### 7.3 审核中章节

审核中章节允许在养号期进行状态核验，但不会触发新章节发布。

程序会进入章节详情刷新平台状态：

- 平台仍审核中：飞书保持审核中
- 平台已发布：飞书更新为发布成功

## 8. 端口变更操作

### 8.1 连接新端口

```powershell
$adbExe = 'C:\Users\Administrator\AppData\Local\Android\Sdk\platform-tools\adb.exe'
& $adbExe connect 127.0.0.1:端口
```

### 8.2 核对设备身份

```powershell
& $adbExe devices -l
```

优先根据 `model` 与历史设备型号对应；随后通过脚本冷启动并读取 `uiautomator` 文本树中的作品标题做二次确认。

### 8.3 同步两个位置

端口变更后必须同时修改：

1. `config\config.yaml` 中的 `adb.devices`
2. 飞书“账号管理表”中的“红手指设备ID”

只修改其中一处会导致错误设备发布。

修改期间应先停止持续服务，修改完成并验证后再启动。

## 9. 日志与运行分析

主要日志：

| 文件 | 内容 |
|---|---|
| `logs\closed_loop.stderr.log` | 网关启动、调度器启动、后台异常 |
| `logs\closed_loop.stdout.log` | 本地网关健康检查和发布HTTP请求 |
| `logs\closed_loop.service.log` | Windows 启动脚本合并日志 |
| `logs\openclaw.log` | 应用历史日志和健康检查 |

查看最新日志：

```powershell
Get-Content -Encoding utf8 logs\closed_loop.stderr.log -Tail 100
Get-Content -Encoding utf8 logs\closed_loop.stdout.log -Tail 100
```

判断系统健康需要同时检查：

1. `closed_loop.py --continuous` 进程存在
2. 网关健康检查返回 HTTP 200
3. 日志没有持续异常堆栈
4. 五台 ADB 设备在线
5. 飞书章节任务状态合理
6. 飞书发布记录表有对应成功或失败记录

## 10. 常见异常处理

### 10.1 `device is not connected`

处理：

1. 执行 `adb connect`
2. 执行 `adb devices -l`
3. 确认状态为 `device`
4. 再运行一次 `closed_loop.py --once`

### 10.2 作品不匹配

典型错误：

```text
cannot ensure work from current Fanqie page
```

处理：

1. 立即停止该账号的新发布
2. 核对设备型号、端口和番茄登录账号
3. 核对设备实际作品标题
4. 修正配置文件和飞书账号表
5. 不要在错误作品上强制继续

### 10.3 页面停留在每周任务或消息中心

当前脚本会自动：

1. 返回主页面
2. 点击作品
3. 等待作品列表出现“连载中”或“去创作”
4. 点击第一本作品

如果三次点击后仍未进入作品页，任务会失败并记录原因，不会盲目点击。

### 10.4 登录失效、验证码、升级弹窗

此类页面不在自动发布范围内。处理：

1. 暂停对应账号
2. 人工完成登录、验证码或应用升级
3. 手工回到番茄作家助手主页面
4. 运行一次单次扫描验证
5. 恢复持续服务

### 10.5 达到三次发布失败

章节会变为：

```text
发布失败/Publish Failed
```

处理：

1. 先查看飞书发布记录表中的最后失败原因
2. 修复设备或配置问题
3. 将流程重试次数重置为数值 `0`
4. 将发布状态恢复为待发布或审核中
5. 执行单次运行验证

不要只重置次数而不处理根因。

## 11. 测试与验收

运行全部自动化测试：

```powershell
.\.venv\Scripts\pytest.exe -q
.\.venv\Scripts\mypy.exe .
```

当前验收流程：

1. 在飞书创建一章全新测试任务
2. 完成正文生产和人工审核
3. 设置计划发布时间
4. 执行单次运行
5. 确认目标设备执行完整冷启动
6. 确认进入正确作品
7. 确认章节号、标题和正文完整
8. 确认选择“有使用AI”
9. 确认平台状态为审核中或已发布
10. 确认飞书状态和发布记录正确
11. 确认设备回到章节管理页
12. 再执行一次，确认不会重复发布

以上步骤通过后，可以进入持续无人值守运行。

## 12. 日常巡检清单

建议每天检查一次：

- [ ] 五台 ADB 设备均在线
- [ ] 持续服务进程存在
- [ ] 日志没有连续异常
- [ ] 飞书没有长期卡住的待发布任务
- [ ] 发布失败任务都有明确失败原因
- [ ] 审核中章节能够刷新状态
- [ ] 番茄账号没有登录失效
- [ ] 云手机没有升级或验证码弹窗
- [ ] 设备映射没有被端口变化破坏
- [ ] 新发布章节没有重复

## 13. 安全注意事项

- 不要在日志、截图或 Git 中保存账号密码、飞书密钥和模型 API Key。
- 不要同时启动两个持续服务，否则可能重复扫描和争抢网关端口。
- 不要在服务运行时直接交换设备端口。
- 不要删除飞书发布失败记录，它们是排查历史依据。
- 不要通过强制修改飞书状态掩盖设备端实际失败。
